# 26-第三周复盘与总结（TCP / HTTP / 抓包）

## 一、这周学了什么

- **链路与地址**：IP 跨网、MAC 同链路、ARP 把 IP 换成 MAC；交换机按 MAC 表转发。
- **网络层**：IPv4 首部 5 行、首部长度 ×4 字节、片偏移 ×8 字节；分片时每片最多 ⌊(MTU−20)÷8⌋×8 字节。
- **传输层**：三次握手（SYN / SYN+ACK / ACK）、四次挥手、TIME-WAIT；滑动窗口、拥塞控制、超时重传；端口三段与四元组。
- **应用层**：HTTP 请求与响应各四部分；Host 指定站点；GET 参数在 URL、POST 在请求体；表单编码与明文风险；状态码 2xx/3xx/4xx/5xx。
- **实操**：虚拟机抓 DNS、抓 TCP 握手、抓 http 表单、写抓包分析报告；网络实验室 7 个实验全部跑通。

## 二、卡在哪

- **TTL 有两个含义**：DNS 记录的 TTL 是缓存秒数，IP 首部的 TTL 是还能经过几个路由器。混过一次，已纠正。
- **交换机与路由器**：交换机在数据链路层按 MAC 转发，路由器在网络层按 IP 选路。曾把交换机选成网络层。
- **字段概念**：分不清“字段名 / 字段值 / 端口 / 协议号”；实验六的「命题→证据」还没全过。
- **GET 与 POST**：一开始只记得“一个请求数据、一个发送数据”，没抓住“参数放在哪”。
- **窗口方向**：看到 Window 64240 时，误以为是服务器的窗口；实际是发这个包的一方通告的接收窗口。

## 三、全链路默写

```
DNS   域名 → IP        看 Transaction ID 配对、Answer 里的 A 记录、TTL
TCP   建立连接         看 SYN / ACK / seq，三次握手确认双方收发能力
HTTP  发请求           看请求行（方法 + 路径）、Host
HTTP  收响应           看状态码、Content-Type
表单  提交 POST        看 Content-Type 与正文 username=…&password=…
```
