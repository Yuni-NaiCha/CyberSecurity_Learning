# 17-第二周复盘与总结

## 一、这一周的主线

第 2 周学的是「地址怎么找、页面怎么来」。四块拼起来：**ARP 与交换机**管同一个局域网内怎么走到对方，**IPv4 与子网**管地址怎么分、怎么算，**DNS** 管名字怎么变成地址，**HTTP** 管页面怎么传过来。

---

## 二、ARP：从 IP 到 MAC 的那一步

同一局域网里，知道对方 IP 还不够，得先拿到 MAC 才能把帧发出去——ARP 干的就是这件事：**请求广播、应答单播**。

这周在两端各看了一遍 ARP 表：

| 系统 | 命令 | 看到什么 |
|---|---|---|
| Ubuntu | `arp -n`、`ip neigh` | 基本只有网关，`ip neigh` 多一列状态字段 |
| Windows | `arp -a` | 按接口列全量，自带不少静态组播表项 |

两端对比出来四条：底层都是 IP 与 MAC 的映射；MAC 写法不同（Windows 用 `-`，Linux 用 `:`）；Linux 的状态字段更直观；Windows 初始表项多，Linux 初始很干净。

ARP 表项有动态、静态之分，会老化——不通信的条目过一段时间就没了。

---

## 三、交换机：MAC 表怎么建、帧怎么转

**集线器**在物理层工作，收到的信号往所有端口广播，所有端口共享一个冲突域；**交换机**在链路层工作，按 **MAC 地址表**转发。

自学习的过程说白了三步：

1. 收到帧，先记「**源 MAC ↔ 入端口**」写进表；
2. 查目的 MAC 在不在表里：在，就从对应端口发；
3. 不在，就从除入端口外的所有端口**泛洪**；表项也有老化时间。

交换机隔离的是**冲突域**，不是广播域——广播域要靠 VLAN 或路由器来切。

---

## 四、IPv4 与子网：从分类到 VLSM

这一周把 IPv4 从「分类编址」一路推到「CIDR + VLSM」：

- 分类：A（1–126）、B（128–191）、C（192–223）、D（224–239，多播）、E（240–255，保留），各有默认掩码；
- 子网划分：借主机位当子网位，块大小法比背公式省事；
- CIDR：地址块用「网络前缀/长度」表示，路由聚合就是把连续的小块合成大块；
- VLSM：同一个大网段里按需求切不同大小的子网。

周末用纸笔、不查答案做了 10 道手算题，结果如下：

| 题 | 考点 | 结果 |
|---|---|---|
| 1 | 地址分类与默认掩码 | 3/4，把 `172.16.5.9` 判成了 C 类 |
| 2 | /24 等分四个子网 | 全对 |
| 3 | /20 求真网络/广播/范围/主机数 | 前四问对，主机数漏减 2 |
| 4 | /26 求四项 | 总地址数写成 256（应为 64） |
| 5 | /22 块落在第三段 | 终点写成 24（应 23）、主机数漏减 2 |
| 6 | 判断是否同网段 | 全对 |
| 7 | /22 /28 /30 可用主机数速算 | 全对 |
| 8 | 路由聚合 | 掩码写成 192（应 252）、块写成 64（应 4） |
| 9 | VLSM 分配 | 方案对，D 的掩码写成 /28（应 /30） |
| 10 | /11 大网段 | 全对 |

**4 题全对，失分集中在三个地方**，而且反复出现：忘了减 2、边界差一位、掩码表不熟。前两个是习惯问题，最后一个是记忆问题。

## 五、DNS：从域名到 IP

- **域名结构**：根 → 顶级域（TLD）→ 二级域 → 主机名，从右往左读；
- **服务器层级**：根服务器、顶级域服务器、权限（权威）服务器，加上本地 DNS 服务器；
- **递归与迭代**：客户端只问本地 DNS 一次，这是**递归**；本地 DNS 自己一个个去问根、顶级、权威，这是**迭代**——跑腿的是本地服务器；
- **记录类型**：`A` 填 IPv4，`AAAA` 填 IPv6，`CNAME` 填**另一个域名**（别名，不是 IP）；
- **Transaction ID**：一问一答的唯一单号，用来把应答和请求配对；
- **TTL**：缓存有效期，秒为单位。

双端抓包里看到一条完整的 CNAME 链：`www.baidu.com` → `www.a.shifen.com` → `www.wshifen.com`，最后才跟两条 A 记录 `103.235.46.96` / `103.235.47.188`。CNAME 的 TTL 是 731 秒，A 记录只有 104 秒——别名不常变，具体机器随时会换。

还有一个反向收获：Win10 端怎么都抓不到明文 DNS，逐项排除后确认是**加密 DNS（DoT/DoH）**在起作用——这比抓到包更有价值，说明「抓不到」本身也是结论。

## 六、HTTP：页面怎么传

- 应用层的两种形态：**C/S**（客户/服务器，像饭店点菜）和 **P2P**（对等，像群聊）；
- HTTP/1.0 是**非持续连接**，每次请求都要重新建 TCP；HTTP/1.1 是**持续连接**（keep-alive），可以复用；
- 报文分**请求**（请求行 + 首部 + 正文）和**响应**（状态行 + 首部 + 正文）；
- 方法：GET 取、POST 提交；状态码：200 / 301 / 302 / 403 / 404 / 500；
- **Cookie**：HTTP 本身无状态，靠它做「VIP 卡」记住身份；
- **Web 缓存**：靠 Expires 判断有效期，过期带上 `If-Modified-Since` 去问，没变就回 **304 Not Modified**。

---

## 七、三个卡点与修正

1. **忘了减 2**：每题收尾固定问一句「这问的是总地址数，还是可用数」。
2. **边界差一位**：终点 = 起点 + 块 − 1，块大小是「数几个」，不是「加到几」。
3. **掩码表不熟**：`/20 /22 /23 /26 /27 /28 /29 /30` 必须张口就来，这是记忆问题，不是算术问题。

另外两条概念上的修正：**CNAME 不是跳转**（301/302 才是跳转，DNS 层只是别名）；**递归和迭代别把主语搞反**——「本地 DNS 去问根」那一步是迭代。

---

## 八、方法上的收获

- **双端对比**比单端记录有用：ARP 表、DNS 抓包都是两端一起看，差异本身就是知识点。
- **二进制画图**能在算错时快速定位是哪一位错了。
- **抓包验证理论**：书上说的 Transaction ID、CNAME 链、TTL，在包里都能指出来；指不出来就说明没真懂。
- 「抓不到」也要追到底——加密 DNS 那次，结论比数据更有价值。

---

## 九、一句话总结

第 2 周把「地址」这条线打通了：**MAC 与 IP 解决「谁在哪」，子网解决「在不在同一个网」，DNS 解决「名字怎么变地址」，HTTP 解决「页面怎么传」**——这四块拼起来，就是「输入网址到页面显示」的骨架。
