# 18-TCP 与 UDP 五项对照

> 第 3 周 周二 · 2026-11-25
> 先闭卷在纸上填了五格，再对照 16 号（TCP 握手挥手）和 12、13 号（DNS）补的机制。
> 一句话：**TCP 是先打电话确认再说话，UDP 是发完就挂。**

---

## 一、五行对照表

| | TCP | UDP |
|---|---|---|
| **连接** | 先三次握手建立连接，再发数据 | 不建连接，直接发 |
| **可靠** | 丢包能发现，会重传 | 不管丢没丢，发出去就不负责 |
| **有序** | 每个字节有序号，乱序到达也能按号重排 | 没有序号，先到先交 |
| **速度** | 要等确认、要重传，慢 | 无连接无确认，开销小，快 |
| **场景** | 网页、文件下载、SSH、邮件 | DNS 查询、直播、在线游戏、视频通话 |

---

## 二、逐行解释

### 1. 连接

**硬核**：TCP 传输数据前要先完成三次握手（SYN → SYN+ACK → ACK），双方确认收发能力后才开始传；结束后要四次挥手。UDP 没有握手，构造好报文直接交给 IP 层发出去。

💬 **大白话**：TCP 是打电话，先“喂，能听见吗”确认两遍再说话；UDP 是往对方信箱塞纸条，塞完就走，不管他在不在家。

### 2. 可靠

**硬核**：TCP 给每个字节编号，接收方回 ACK 确认；超时没收到确认就重传。UDP 没有 ACK、没有重传，丢了就是丢了，协议层不告诉你。

💬 **大白话**：TCP 是快递要签收，没签收就再送一次；UDP 是撒传单，风刮走几张也没人管。

### 3. 有序

**硬核**：TCP 的序号让接收方能把乱序到达的报文段重新排好，再交给应用层。UDP 没有序号，网络先送到哪个就交哪个，顺序由应用自己处理。

💬 **大白话**：TCP 收快递会按单号排队；UDP 是一把信倒桌上，谁先到谁在上面。

### 4. 速度

**硬核**：TCP 慢在三处——建连要一个 RTT、每个数据段要等确认、丢了要重传；它还有流量控制（怕对方收不下）和拥塞控制（怕网络堵）。UDP 没有这些，头部只有 8 字节，发出去就不管。

💬 **大白话**：TCP 像挂号排队，一步一确认，稳但慢；UDP 像扔纸飞机，快，但可能半路掉。

> 注意：不是“TCP 天生慢”。**是它为了保证不丢不乱，多花了这些成本。** 网络好的时候两者差距不大。

### 5. 场景

**硬核**：
- 网页、文件、邮件、SSH → 少一个字节内容就坏了，**必须可靠** → TCP
- DNS 查询、直播、游戏、视频通话 → 数据小、要快、丢一点能忍（重发反而更卡）→ UDP

💬 **大白话**：传合同用挂号信（TCP），喊一嗓子“开饭了”用嗓子（UDP）——喊漏了再喊一遍就行。

---

## 三、两个容易混的点

**① “可靠” ≠ “有序”**
可靠是**丢了能不能补**；有序是**到了能不能排整齐**。两件事，TCP 都做，UDP 都不做。

**② “UDP 快”不是因为它更高级**
是因为它**少做了事**。要可靠又要快，就得在应用层自己补（QUIC / HTTP/3 就是干这个的，跑在 UDP 443 上）。
